## Why

Second change of 0.3 (`docs/ROADMAP.md`). A text program reads characters
one by one and must know when its input ends; numbers are read as reals, not
only integers; a Char is classified (letter, digit, space) before it is
used; and real literals need exponents for very large and very small values.

Request (Marcelo Fortes, 2026-10-21): implement version 0.3: conversions between numbers and text, Split/Join, literals with exponents, `Get(C)` and Char classification.

Approval (Marcelo Fortes, 2026-10-21), answering the decisions proposed to
him, of which this change carries B5, C1, C2 (for Float and Float32) and
C3: A, B and C approved in full; separate PRs, easier to test.

Risk: normal (new runtime functions, a lexer rule, no change to an existing
runtime function, exception lowering or memory ownership).

Status: **implemented** (canon r3.89). `Get` of Currency and Crypto (C2)
comes with the change that gives them values.

## What Changes

1. **B5, exponents.** A real literal may end with `e` or `E`, an optional
   sign and digits, after its fraction: `1.5e3`, `2.0E-7`. `1e3` (no
   fraction) and `1.5e` (no digits) are errors that show the way. A real
   literal or Const beyond Float64 is a compile error (with exponents it can
   be written); beyond Float32 where a Float32 is expected, as before.
2. **C1, Get(C) and EndOfInput.** `Get(C)` reads the next character exactly,
   a space and `'\n'` included, in UTF-8; `GetLn(C)` reads one character and
   the rest of its line (unless the character was the line end).
   `EndOfInput` (Bool, Std.IO) is true when nothing is left. Reading a Char
   past the end stops with "end of input" (kind 18, r3.88); bytes that are
   not UTF-8 with "invalid UTF-8 input"; a Char Range checks the value.
3. **C2, Get of a real.** `Get(F)` of a Float or Float32 skips white space
   and reads an optional `-`, digits, an optional fraction and exponent,
   then white space or the end (`3` is a valid Float). Anything else stops
   with the new category "invalid number input" (kind 19), a value beyond
   the type with "value out of range". A Float32 is rounded once from the
   text, as a literal.
4. **C3, the classes of a Char** (`Use Std.Strings`): `IsLetter` (L*),
   `IsDigit` (Nd: any script's decimal digits), `IsSpace` (White_Space),
   `IsUpper` (Lu), `IsLower` (Ll), `IsPunctuation` (P*), and `UpperCase(C)`,
   `LowerCase(C)` of a Char, one Char to one, by Unicode 15.1, never a
   locale. The tables are generated by `tools/gen_unicode_tables.py`.

## Capabilities

### Modified Capabilities
- `language/reals`: exponents; reading reals.
- `language/chars`: reading a Char.
- `stdlib/strings`: the classes and case of a Char.
- Constitution CANON-2 (literals), CANON-14 (String functions), CANON-17
  (Get; reading a Char; real input), CANON-19 (trap categories).

## Impact

- Lexer: exponents; `1e3` rejected.
- Analyzer: Get of Char, Float, Float32; `EndOfInput`; the Char classes and
  the Char overloads of UpperCase/LowerCase; real literals beyond Float64.
- Emitter: `emitInputReadCharacter`, `emitInputReadReal`, `EndOfInput`; the
  Char functions.
- libinoxrt: `__inox_con_get_char`, `__inox_con_at_end`, `__inox_con_get_f64`,
  `__inox_con_get_f32` (ConsoleRuntime.cpp); `__inox_char_is`,
  `__inox_char_case` (StringFunctions.cpp); class tables in
  `UnicodeTables.inc`.
- `EndOfInput` becomes a predefined Std.IO name.
