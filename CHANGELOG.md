# Changelog — Inox compiler

This file tracks the versions of Inox, the language and its compiler, which
share one version (constitution VERSIONING). Numbers such as `v3.57` or
`r3.61` are canon revisions, entries of the decision log
(`docs/openspec/specs/constitution/revisions.md`), not versions.

## Unreleased

### Changed
- Every compile error says where (canon r3.112, E14, change `source-positions`): `path:line:column: parse error: message` and `path:line:column: semantic error: message`, the form editors read. A semantic error names the statement, declaration or contract clause being checked, in the file of its module, and an error in a generic instance the line of the generic body. **Changed output:** a parse error read `parse error at 12:5: message` and had no file; a semantic error had no position.
- Every quality gate runs in CI (canon r3.111, E19, change `ci-gates`): a new Gates workflow runs the suite under ASan+UBSan with a 1 MiB stack, mutation fuzzing (seeds 1 and 7) and the arithmetic differential test on every pull request that touches code, on main and nightly, and the IR snapshot against the base on pull requests labelled `refactor`; CI checks that the version and canon revision agree in every document (`tools/version_check.py`). `tools/ir_snapshot.py --allow` also accepts programs that a change adds.
- The compiler phases have written contracts (canon r3.110, E11, change `phase-contracts`): `docs/ARCHITECTURE.md` says what each phase receives, produces and must never do, which files own it, and where the code still deviates (D1-D7). The roadmap gains a foundation milestone before 0.5, with no new language feature (F0-F7).
- `ref` and `Self` are read-only through owners (canon r3.109, CANON-10, CANON-25, change `read-only-through-owners`). **Breaking:** with `ref H THolder` and `FChild Own<TNode>`, `H.FChild.FValue := 1`, a `ref mut` argument, a `Self mut` call, `Value(P) :=`, `Free`/`Move` or `Link(H.FChild)` on what H owns are now compile errors, and so are the same through a plain `Self`; declare `ref mut H` or `Self mut`. `Free(P)` of a `ref P Option<Own<T>>` is rejected. A value owner parameter and a path through a `Link` stay writable. No existing test or example changes.
- CANON-1 Safety defaults no longer says "no integer `/`", left over from before r3.95: it says "no unchecked integer division" (canon r3.108, change `canon1-integer-division`). No rule changes.
- The capability specs cover contracts, safe pointers, method reuse and `Std.Debug` (canon r3.107, change `fold-spec-deltas`): new `language/contracts`, `language/pointers` and `stdlib/debug`; `language/structs` gains method reuse, `Override` and methods of built-in types. The rules were already law; only the specs change.
- A Range of Integer is a type of its own, as Ada's `type T is range` (canon r3.106, CANON-13, change `range-types`). Its values compute and compare with values of the same Range and with constants; `D + D`, `-D` and `IIf(C, D, 0)` belong to the Range and are checked when stored, and `N := D * 2` declares one. **Breaking:** two Ranges, or a Range and an Integer variable, no longer mix in arithmetic, comparisons, `in`, IIf, assignments or arguments: write `Integer(D)`, `TMeters(I)` or `TMeters(S)`. Before, `Meters + Seconds` compiled, and a TDateTime passed where a TDuration was expected gave a wrong instant. A Range value still indexes an array and is printed by Put and PutLn. Std.DateTime converts internally; its interface is unchanged.
- Std.DateTime names its parts in full, in the order of ISO 8601 (canon r3.105, change `datetime-names`): `EncodeDate(Year, Month, Day)`, `EncodeDateTime(Year, Month, Day, Hour, Minute, Second)`. **Renamed**, as in Delphi's DateUtils: `Year`, `Month`, `Day`, `Hour`, `Minute`, `Second`, `MicroSecond` are now `YearOf`, `MonthOf`, `DayOf`, `HourOf`, `MinuteOf`, `SecondOf`, `MicroSecondOf`. ISO 8601 is the format of exchange; `dd/mm/yyyy` and other regional formats come only from `FormatDateTime`.
- Repository layout (canon r3.104, change `repo-layout`): `src/runtime/`, `tools/scripts/` (the test runners: `bash tools/scripts/run-tests.sh`), `tests/ci/`, `docs/BUILD.md`, legal notices in `licenses/`; `contrib/` (editors, tree-sitter, shell completions, CI templates, Docker), `include/inox/`, `libs/_template/` and `utils/` (inox-fmt, inox-lint, inox-pkg, inox-lsp) say in READMEs what belongs there; tests no longer leave files in the repository.
- Test and example programs use English names and texts (canon r3.103, change `english-programs`): about 130 identifiers and the Portuguese strings of the programs, with their expected outputs, and the code illustrations of the documents.
- The records state decisions, in English (canon r3.102, change `decisions-not-dialogue`): the constitution, the specs, the OpenSpec changes, the revision log, the history, the roadmap and code comments no longer quote chat messages; each says what was decided, by Marcelo Fortes, and when.

## 0.4.0 pre-alpha

Modules and encapsulation, with the work planned for 0.3 (numbers, text and
the basic library), which was never released apart (canon r3.101).

### Added
- Modules and encapsulation (canon r3.99, CANON-3, change `modules-encapsulation`). Each module has its own names: a name is the module's own declaration first, then the one public declaration among the modules it uses, and two of them is an error that names the qualified forms. `Bank.Accounts.Fee` reaches a public name of a used module; `Use Bank.Accounts as Accounts` gives it a name local to the file; `Use Bank.Accounts.(Deposit, Withdraw)` takes only those names unqualified. Everything is private unless `Public`, the last word of a header (`TPerson Struct(TBeing) Public`, `TPerson.Rename(Self mut, Name String) String Public :`, `Const MaxRate Public := 0.05`) or the line that opens a struct's public fields; State is never public. `Use` is not transitive, and `Export Use M` passes M on (the library pairs use it). A struct's private fields and methods are reached only in its module, a struct with a private field without default is built only there, reuse across modules sees public members, and an outside write to a public field still checks the invariant. `--path <dir>` and `INOX_PATH` add directories where modules are searched; `Std` names only the standard library. `inox interface File.inox` prints what other modules see. `examples/bank` is a bank in four files.

### Changed
- `Public` is a reserved word; `Export` and `as` are words only in `Export Use` and `Use M as A`. A program that used another module now marks with `Public` what that module offers.
- Releases follow the version (canon r3.101): when a push to `main` carries a version that has no tag yet, CI builds Linux and Windows in Release, runs the suite, packages, extracts and runs the packages, and publishes `vMAJOR.MINOR.RELEASE` as the latest release, with this changelog's section as notes and the stage in its title. The build reads its version from `Version.h`. 34 completed OpenSpec changes are archived.
- The grammar and OpenSpec live under `docs/` (canon r3.100, change `docs-layout`): `docs/grammar/grammar.ebnf` and `docs/openspec/`. OpenSpec commands run from `docs/` (`cd docs && openspec validate --all --strict`). `docs/openspec/config.yaml` was invalid YAML and OpenSpec had been ignoring the project's rules; it is fixed.

### Fixed
- The packaged compiler run through PATH (`inox run f.inox` after `set-inox-env`) did not find libinoxrt beside itself: it took the directory it was run from for its own. It now asks the operating system where it is (Linux, Windows, macOS, FreeBSD), and searches PATH as a last resort. Found by the new release smoke test.
- A method argument was not analyzed against its parameter: `A.Deposit(500.00)` with a Currency parameter was rejected as Float64. It is analyzed like a routine argument.

### From 0.3: numbers, text and the basic library

#### Changed
- Programs are optimized by default (canon r3.98, CANON-23, change `optimize-default`): `inox run`, `inox build` and `inox file.inox` call clang with `-O2`, and `--debug` before the file builds with `-O0`. Before, every program was built without optimization: an arithmetic loop of 300 million steps took 1.99 s and now takes 0.41 s, the time of the same loop in C -O2. Checks are unchanged.

#### Fixed
- `shl` on an Integer dropped the bits that left Int64 silently (`(2 ^ 62) shl 2` was 0); it is now the product A * 2^N, checked as on UInt64: a constant beyond Int64 is a compile error, a run-time one stops with "integer overflow" (canon r3.97, CANON-8, change `expression-checks`). Found by the new expression test.
- `4(5 * (2 + 2))` and `(2 + 3)(4)` were accepted by the analyzer as calls and failed only in code generation; they are now rejected naming the `*` to write, as is `X(2)` for a variable (change `expression-checks`). `1 < X < 10` gets a message that comparisons are not chained.

#### Tests
- The arithmetic differential test is rewritten: random expressions with only the parentheses CANON-20 requires, checked against an independent parser and evaluator of the law, folded and at run time, and with expressions that must trap; `tests/runtime/math-expressions.inox` holds 152 written expressions.

#### Changed
- `mod` and `rem` as in Ada (canon r3.96, CANON-8, change `ada-modulus`): `mod` now has the sign of the divisor (`-7 mod 2` is 1, it was -1), and the new reserved word `rem` gives the remainder with the sign of the dividend (`-7 rem 2` is -1, what `mod` gave before). With non-negative operands both are as before.
- `/` divides as in Ada (canon r3.95, CANON-8, change `integer-slash`): two integers give the integer division, truncated toward zero, which `div` gave before; two reals or two decimals their division. An integer and a real are never mixed without a conversion. `/=` now divides an Integer too, and a constant zero divisor of integer `/` is a compile error. `mod` is unchanged.

#### Removed
- `div` is no longer a reserved word (canon r3.95): it is an ordinary name, and `A div 2` is a parse error. Every program, test, example and the standard library now write `/`.
- The migration diagnostic for the old `Var` block (canon r3.94, CANON-4, change `remove-var-diagnostic`): `Var` is an ordinary name, and a `Var` block or `Var X := 1` now fails with the generic message of any unexpected text. `mut` stays reserved.

#### Added
- Explicit discard (canon r3.93, CANON-7, change `discard-results`): `_ := F(X)` calls a function or a method for its effect and drops its result on purpose; a function alone as a statement (E2) and an unread local (OPEN-4) stay compile errors, and the E2 message now shows both `X := F(...)` and `_ := F(...)`. `_` is a discard target, not a variable: it is never read, declared, compounded or chained, and only a call with a result is discarded (not a literal, a variable, a field, an operation, a conversion or a construction). The call runs once, with its exceptions and contracts, and an owned result is released. **Fixed:** a line at module level that is no declaration (`+ Integer : ... ;`) was silently ignored; it is now an error.
- Std.DateTime, Std.DateUtils and Std.SystemUtils (canon r3.92, CANON-18, CANON-23, change `datetime-systemutils`). A `TDateTime` counts microseconds since 0001-01-01 (proleptic Gregorian), a `TDate` days, a `TDuration` microseconds; `EncodeDate`, `EncodeDateTime` (a date that does not exist breaks a precondition), `DecodeDate`, `Year` .. `MicroSecond`, `DayOfWeek`, `AddDays`, `AddSeconds`, `DaysBetween`, `IsLeapYear`, `DaysInMonth`, `NowUTC`, `Now`, `ToLocal`, `ToUTC` (UTC and the system's zone only). Std.DateUtils: `ToISO8601`, `FromISO8601` (raises `ConversionError`), `FormatDateTime` with Delphi's codes. Std.SystemUtils: `ParamCount`, `ParamStr(I)`, `GetEnv`, `EnvExists`, `Halt(Code)`, `Sleep(Ms)`, `CurrentDir`, `PlatformName`, UTF-8 on every system. `inox run file A B` and `inox file A B` pass arguments to the program, and a non-zero exit status is reported and returned. `examples/edit.inox`: a micro-editor with Emacs keys. **Changed:** a missing module is now diagnosed with Std.Process as the example of a module not yet written.
- Currency and Crypto (canon r3.91, CANON-8, CANON-17, CANON-19, change `decimals`): Currency is an exact decimal with 6 places (an Int64 scaled by 10^6), Crypto one with 18 (an Int128 scaled by 10^18). A literal where one is expected, or next to one (`Price * 3`), is read exactly; more places than the type holds or a value beyond it is a compile error. `+` and `-` are exact; `*` and `/` are exact and then rounded half to even to the type's places; an Integer variable, a Float or the other decimal is converted explicitly (`Price * Currency(Count)`). `Integer(C)` truncates; `Std.Math` gains `Round` (half to even) and `Trunc` for reals and decimals; `Crypto(C)` is exact and `Currency(Cr)` rounds half to even; `Currency(S)` reads text. A decimal is written with at least two decimals (`19.99`, `5.00`, `0.123456`) and read by `Get`. Decimals live in locals, parameters, results, fields, arrays, State and Consts (`Const Fee := Currency(2.5)`). New runtime error "decimal overflow".
- **Fixed:** a negated real literal (`-0.1` as a Float32, `-1_000.5`, `-2.5e2`) produced invalid IR.
- Numbers and text (canon r3.90, CANON-8, CANON-14, CANON-15, CANON-17, change `numbers-text`). `String(N)` and `String(F)` write a number as Put does; `FormatFloat(F, Decimals)` (Std.Strings) fixes the decimals (0..20). `Integer(S)`, every integer type (`Byte(S)`, a Range), `UInt64(S)`, `Float(S)` and `Float32(S)` read the whole text (an optional minus and digits; for a real a fraction and an exponent); anything else raises the new exception `ConversionError`. `FieldCount(S, Sep)` and `Field(S, Sep, I)` (Std.StrUtils) split a line; Split and Join come with the collections of 0.5. **Changed:** a real is written as the shortest text that reads back as the same value (`0.1`, `2.5`, `1500.0`, `0.30000000000000004`, `1.0e16`, `NaN`, `Inf`), on the console, in files and by `String(F)`, instead of six decimals (`2.500000`); a Float32 writes its own shortest text.
- Reading characters and reals, Char classes, real exponents (canon r3.89, CANON-2, CANON-14, CANON-17, CANON-19, change `input-chars-exponents`). `Get(C)` reads the next character exactly, spaces and line ends included (UTF-8; "end of input" past the end); `GetLn(C)` also consumes the rest of the line; `EndOfInput` is true when nothing is left. `Get` of a Float or Float32 reads `-12.5`, `3` or `1.5e3` strictly (a Float32 rounded once from the text); anything else stops with the new runtime error "invalid number input". `Use Std.Strings` gives `IsLetter`, `IsDigit`, `IsSpace`, `IsUpper`, `IsLower`, `IsPunctuation` and `UpperCase(C)`/`LowerCase(C)` of a Char, by Unicode 15.1. Real literals take an exponent after the fraction (`1.5e3`, `2.0E-7`); `1e3` is an error, and a real literal beyond Float64 is a compile error. `EndOfInput` is a new predefined Std.IO name.
- The console and Std.Terminal (canon r3.88, CANON-7, CANON-17, CANON-18, CANON-19, change `console-abi-terminal`). The console belongs to libinoxrt (`runtime/ConsoleRuntime.cpp`): `Put`, `PutLn`, `Get` and `GetLn` call it, generated code no longer calls `printf` or `getchar`, and every program links libinoxrt. Output stays in order, a prompt written with `Put` is shown before the program waits for input, and on Windows the console runs in UTF-8 with VT sequences and is given back at exit. `Use Std.Terminal` gives `RawMode`, `ReadKey` (a `TKey` with `Kind`, `Ch`, `Ctrl`, `Alt`: characters, arrows, Home, End, PageUp, PageDown, Enter, Backspace, Delete, Tab, Escape, F1..F12), `ScreenSize`, `MoveTo`, `ClearScreen`, `ClearLine`, `SetColor`/`ResetColor` with 16 colors, `ShowCursor` and `Flush`; the terminal is given back however the program ends (end of Main, a runtime error, an unhandled exception, a signal). With a file or a pipe as input, `ReadKey` reads the same keys from the bytes, so full-screen programs are testable. New runtime error "end of input" (ReadKey past the end). `examples/keys.inox`.
- **Breaking:** a function or method called as a statement is a compile error, as in Ada (canon r3.88): `Twice(2)`, `Answer` or `C.Next` alone show `X := Twice(...)`. Before, the result was dropped silently.

## 0.2.0 pre-alpha — unreleased

### Added
- `!=` (canon r3.87, CANON-2, change `not-equal-operator`): inequality is written `#` or `!=`, one operator; a lone `!` is an error that points to `not`.
- Floating-point policy (canon r3.86, CANON-8, change `float-policy`): a Float32 literal is rounded once from its digits, never through a Float64 (`1.000000059604644775390626` is above 1 as a Float32); a Const that is a real literal is universal, a Float32 where a Float32 is expected (`A Float32 := Pi`), while a computed Const and every variable keep their precision; Std.Math's Pi, Tau and E carry 37 significant digits. `Float32(F)` rounds to nearest even, traps on a finite overflow, keeps NaN and the infinities and gives signed zeros on underflow.
- `case` on a String (canon r3.85, CANON-12, change `case-strings`): the selector may be a String; each choice is a String literal or a String Const, compared byte for byte as `=` compares, several sharing an arm with `|`. Ranges of Strings, a String repeated (also through a Const), a variable as a choice and a String case without `else` are compile errors. A Float selector stays an error.
- Float conversions and real Consts (canon r3.84, CANON-8, change `float-conversions`): `Float(I)` and `Float32(I)` round an integer (a UInt64 read unsigned); `Integer(F)` and every integer type truncate toward zero and stop the program with "integer conversion out of range" for NaN, an infinity or a value that does not fit (a constant is a compile error); `Float(G)` widens a Float32 exactly and `Float32(F)` rounds, stopping with "value out of range" beyond Float32. A conversion into a number takes a number (`Float(True)`, `Integer("7")`, `Float(Heart)` are errors that show the way). A real literal is a Float32 where a Float32 is expected. A `Const` holds a real folded from constants (`Const Half := 1.0 / 2.0`, `Float32(...)`), and Std.Math's `Pi`, `Tau` and `E` are now Consts. Float32 values print and are written to files. Real constants are emitted as exact hexadecimal doubles.
- Char values (canon r3.83, CANON-14, change `char-values`): a Char literal is one Unicode scalar or an escape (`'\n'`, `'\r'`, `'\t'`, `'\0'`, `'\\'`, `'\''`); an empty literal, two characters, another escape or a surrogate are compile errors. `Char(I)` converts a code point, checked ("integer conversion out of range" outside 0..$10FFFF or for a surrogate), `Integer(C)` gives it back, `String(C)` is the one-character String; nothing converts implicitly. Chars compare by code point and form ranges for `for`, `case` and `in`; a Char Range (`TLetter Range 'A'..'Z'`) holds Chars with checked stores, `Low`/`High` and `Set<TLetter>`. No arithmetic, `Ord`, `Succ` or `Pred`. `CharAt(S, I)` in Std.Strings ("string index out of range" outside). `Put`, `PutLn` and `WriteLn` write the character in UTF-8. Chars live in locals, parameters, results, fields (a default or given in the construction), State, arrays (32-bit storage), Consts and generic instances. libinoxrt gains `__inox_str_from_char` and `__inox_str_char_at`.
- Initialization is transitive (canon r3.82, CANON-5, CANON-9, change `array-fill`): a struct field of an enum, array or type-parameter type has no implicit value. It has a default (`FSuit TSuit := Club`, `FData Array[1..4] Byte := Fill(0)`) or is given in the construction, whose omission is an error. A struct takes its type defaults (`P TPacket`, State, `New(TPacket)`) only when every component has one, nested structs and parts included; the error names the field. A field whose type uses a type parameter never has a default, whatever the instance: `D TBox<Integer>` is an error, `TBox(FValue := 0)` a value. **Breaking** for structs with such fields declared without `:=`.
- Arrays are initialized where they are declared (canon r3.81, CANON-5, CANON-13, change `array-fill`): `Fill(Value)` is the array its target expects (a declaration, a State initializer, an assignment, an argument or a Return), with the target's type and bounds, every element (or row of a multi-dimensional array) a copy of Value, evaluated once: `Counts Array[1..100] Integer := Fill(0)`, `Hand Array[1..5] TSuit := Fill(Club)`, `Points Array[1..10] TPoint := Fill(Zero)`, `Grid Array[1..3, 1..4] Byte := Fill(Row)`. A Range element checks the value, each String element holds its own reference, an array of owners is filled with `None`. `Fill` is a predefined name. **Breaking:** an array declared without `:=` (`A Array[1..3] Integer`, also in State) is an error whose message shows the Fill to write, and an enum struct field has no implicit value (r3.82); the first enum literal, zero and False are never implicit values of an array. Structs keep their field defaults.
- **Breaking:** the set functions `With(S, X)` and `Without(S, X)` are `Include(S, X)` and `Exclude(S, X)` (canon r3.81); the old names are errors that show the new ones. The six set functions return a new set and never change their arguments, unlike Pascal's Include and Exclude, so a call as a statement (`Include(S, Club)`) is an error that shows `S := Include(S, ...)`.
- Enum, Range and Set (canon r3.80, CANON-13, change `enum-range-set`): enums (`TSuit (Club, Diamond, Heart, Spade)` or one literal per line) are nominal ordinals: `Ord(E)`, `TSuit(I)` ("integer conversion out of range" outside 0..N-1), `Low(TSuit)`, `High(TSuit)`, `Succ`/`Pred` ("value out of range" past the ends), comparison by order, `for S in Diamond..Spade`, and `PutLn(S)` prints the literal's name as declared; no arithmetic and no Integer conversion either way, an enum variable needs an initializer, a literal belongs to one enum, and a `case` without `else` must name every literal. A Range of Integer (`TScore Range 0..100`, bounds literals or Consts) stops the program with "value out of range" when a value outside it is stored and computes as Integer. `Set<T>` over an enum or a Range of at most 256 values: `[A, B]`, `in`, `=`, `#`, `<=`, `>=`, `Union`, `Intersection`, `Difference`, `SymmetricDifference`, `With`, `Without`, one bit per value. `X in A..B` is lowered. `examples/cards.inox`.
- UInt64 (canon r3.79, CANON-8, change `uint64`): `UInt64`/`UInteger` holds 0..18446744073709551615 in locals, parameters, results, struct fields, array elements and State. `+ - *`, `^` and `shl` stop the program with "integer overflow" above 2^64-1 and below 0; `div`, `mod`, `shr` and the comparisons are unsigned; `case` orders its choices unsigned (and needs `else`) and `for` runs up to 2^64-1. `UInt64(X)` of a negative value and `Integer(U)`, `Natural(U)` or `Byte(U)` outside the target stop with "integer conversion out of range". A literal above Int64.Max is a UInt64 where a UInt64 is expected (`U UInt64 := 18446744073709551615`, `U = $FFFFFFFFFFFFFFFF`); `-U` and `U + I` with an Integer I are compile errors that show the conversion to write; a UInt64 Const is `Const K := UInt64(...)`. `Get`, `PutLn` and `WriteLn` read and print it unsigned. Programs without UInt64 get the same IR as before.
- Std.Strings and Std.StrUtils (canon r3.78, CANON-14, change `std-strings`): `A + B` joins Strings and `S += X` appends; a chain is one allocation and `S := S + X` appends in place when S alone holds its block, so a loop of appends is linear. No implicit conversion: `"N=" + N` is an error. `Use Std.Strings` gives `Length`, `ByteLength`, `Substr`, `Position` (`Pos` is a reserved word), `UpperCase`, `LowerCase`; `Use Std.StrUtils` adds `Trim`, `LTrim`, `RTrim`, `Left`, `Right`, `PadLeft`, `PadRight`, `Replicate`, `Replace`, `Contains`, `StartsWith`, `EndsWith`, `SameText`, `CompareText`. Positions count code points from 1; case mapping, case folding and white space follow Unicode 15.1 (generated tables, `tools/gen_unicode_tables.py`), never a locale. A position outside a String stops the program with "string index out of range" (exit status 70). Without the `Use`, the names are free. libinoxrt blocks gain a hidden header (capacity, character count).
- Generics in their simplest form (canon r3.77, CANON-8, change `generics`): generic routines, `Max<T>(A T, B T) T :`, and generic structs, `TPair<K, V> Struct`. Each use with its types makes an instance (`Max<Int64>`, `TPair<String, Int64>`), checked and compiled like ordinary code, with no cost at run time. Type arguments are inferred, from the arguments (a literal takes the type of the others: `Max(B, 1)` with B Byte is `Max<UInt8>`) or from the target (`Z Integer := Zero`), and never written in an expression (`Max<Integer>(3, 7)` is an error that says so). There are no constraints: T may be any type, also an owner or a File, and an operation it lacks is an error of the instance ("in Max<TPoint>, used in Main: structs cannot be compared with '>'"). Generic routines work across modules and with contracts and exceptions. Methods of generic structs come later; `examples/generics.inox` builds one stack for Integers, Strings and pairs with generic routines.
- Safe pointers (canon r3.73, CANON-25, change `safe-pointers`): `Own<T>`, the single owner of a heap object (`P := New(TNode(FValue := 1))`, `New(TNode)` with defaults), never copied and given away with `Move(P)`; using a moved or freed owner is a compile error on every path; the object, and every object it owns, is freed by `Free(P)`, when the owner is overwritten, or when its routine ends (also by an exception), without recursion. `Option<Own<T>>` for an owner that may be absent (`None`). `Link<T>`, made by `Link(X)` of an owned object, a local, a field, an array element or State, copied freely and born empty; every use checks a generation, so a Link to a freed object, a reused block or a variable whose routine returned never reaches it: `Alive(L)` asks, and a use stops the program with "Inox runtime error: use of a freed object or an empty Link" (exit status 70). Fields with a dot, `Value(P)` read and written, `Same(A, B)`. No pointer arithmetic, conversions, printing or `=` on pointers. `examples/pointers-tree.inox`, `examples/pointers-navigator.inox`; libinoxrt `__inox_own_alloc` / `__inox_own_free`.
- Safe pointers decided (canon r3.71 and r3.72, change `safe-pointers`, design awaiting approval): one owner `Own<T>` and checked references `Link<T>` to any variable, field or array element, permissive with detection, with no reference counting, no garbage collector and no arena for now.
- `examples/reuse-army.inox` (canon r3.69): one behavior for thousands of soldiers, written once per type and reused or overridden, one array per kind; variant structs recorded in FUTURE as the way to mix kinds in one collection (change `variant-structs`, direction only).
- Directions recorded (canon r3.70): encapsulation close to Object Pascal and Rust (change `encapsulation`), routine types as Pascal's procedural types (change `routine-types`), constructors and destructors under analysis (change `lifecycle`); `docs/OOP_COMPARISON.md` lists what object orientation gives and Inox's answer to each point.
- Design by contract, as in Eiffel (canon r3.67, CANON-24, OpenSpec change `design-by-contract`): `pre` (Eiffel `require`) and `pos` (Eiffel `ensure`, with `old X` and `Result`) as the first lines of a routine, each with an optional `, "message"`; `invariant` lines in a Struct, checked after construction, before and after every qualified method call, after a field write from outside and after a `ref mut` argument, and inherited from the reused parts; `pre else` / `pos then` in an `Override` (weaken / strengthen the inherited contract); `invariant` and `variant` on the first lines of a loop (`variant` in while and repeat). A contract only reads (no `Self mut` method, `ref mut` argument or file in it). A broken contract is a runtime trap (CANON-19, exit status 70), not an exception: "Inox runtime error: precondition violated: TStack.Push: ...". The checks are always on in every build through 1.0 (canon r3.68; monitoring levels per module, as in Eiffel, come after 1.0); the backend marks them expected to hold (`llvm.expect.i1`) and keeps the failure path in a `cold noreturn` runtime helper. `examples/contracts.inox`.
- Examples of method reuse and a bank teller (canon r3.66): `examples/reuse-shapes.inox` (one behavior reused by three structs), `examples/reuse-registry.inox` (two parts, Override that combines them), `examples/reuse-inventory.inox` (three levels, arrays, methods of Integer and String), and `examples/bank-atm.inox`, a terminal teller with a numbered menu (balance, deposit, withdrawal, transfer, cancellation, statement) that keeps the accounts and the statement in text files between runs.

Override :` replaces a reused method with the same signature. A name reached by two paths, a field hiding a reused one, a method with a reused name without `Override`, or an `Override` that replaces nothing are errors at the declaration. No subtyping.
- Methods of built-in types (canon r3.66): `String.UpdateStr(Self mut, V String) :`, `Integer.Twice(Self) Integer :`, called on any variable, field or value of that type (`A.FPlan.UpdateStr("x")`, `21.Twice`). A field of `Self mut` can be passed to a `ref mut` parameter.
- `examples/file_io.inox`: a tour of every text-file operation of Std.Files and Std.IOUtils and every way one fails (FileNotFound, AlreadyExists, IOError for a closed file, a file opened for writing and a directory, Retry, ensure, Else, nested try with re-raise, close on exception). The suite now builds and runs every example and compares its output with `tests/examples/NAME.out` (and feeds `NAME.in` when present); an example without an expected output fails, so every program in `examples/` must run. `examples/types.inox` and `examples/type-checking.inox` no longer use Currency, Crypto or Char values, which are not lowered yet.
- Driver commands (canon r3.63, OpenSpec change `driver-commands`): `inox file.inox` and `inox run` build and run (before, `inox file.inox` only checked), `inox build`, `inox check`, `inox emit-llvm`, `inox help`, `inox version`. `--run`, `--build`, `--emit-llvm`, `--help` and `--version` stay as aliases.
- `Std.Debug.Assert(Condition)` and `Assert(Condition, Message)` (canon r3.63, change `debug-assert`): a failed Assert stops the program with "Inox runtime error: assertion failed" (and the message), exit status 70, like an overflow; it is never compiled out.
- Text files (canon r3.59, OpenSpec change `file-io`): `Use Std.IOUtils` gives the type `File` (Std.Files) and `OpenRead`, `Create`, `OpenAppend`, `ReadLn`, `Eof`, `Write`, `WriteLn`, `Close`, `Exists`, `DeleteFile`, `RenameFile`. A File closes itself when its routine exits by any path, also an exception; it is never copied (a local or a `ref mut` parameter). Failures raise `FileNotFound`, `PermissionDenied`, `AlreadyExists`, `DiskFull` or `IOError`, handled with try/except On/ensure/Retry. UTF-8 text, `\n` written on every system. Runtime `runtime/FileRuntime.cpp`; the leak check covers the file programs.
- Bool ordering `false < true` (canon v3.57).
- String ordering (canon v3.56): `<` `>` `<=` `>=` compare Strings byte by byte (Unicode code point order, a prefix first), combining with `not`, `and`, `or`, `xor`, `unless` like any Bool.
- String runtime (canon v3.55, OpenSpec change `string-runtime`): Strings in locals, parameters, results, struct fields (with a String literal default or `""`), array elements, State and `ref` parameters, as reference-counted immutable blocks in libinoxrt that the compiler frees exactly once, also when an exception leaves a routine. `GetLn(S)` reads a line into a String (UTF-8 checked). New runtime faults "out of memory" and "invalid UTF-8 input". `tools/string_leak_check.py` runs the String programs under AddressSanitizer with leak detection in the Linux CI; `inoxrt-tests` unit-tests the runtime on Linux and Windows.

- Type, Const and State sections are parsed into typed declarations (OpenSpec change `declaration-sections`, canon v3.53): a struct field may be a fixed array, `State` may hold structs and arrays (with or without initializer), and malformed entries report their line.
- Struct values (canon v3.52): struct initializers `Q T := Expr`, named construction `T(F := V)` as an expression, nested struct fields and field paths, fields and literal defaults of every scalar type, methods on fields and elements, arrays of struct. A struct that contains itself is a compile error.
- Read-only slices `A[L..H]`, `A[..H]`, `A[L..]`, `A[..]` of type `Slice<T>` (ADR-0017), checked bounds, never outliving their array.
- `ref X T` and `ref mut X T` parameters (ADR-0016): references to the caller's variable, field or array element, with exclusivity checked at compile time.
- Fixed arrays `Array[Low..High] T` with checked indexing, multi-dimensional `M[I, J]`, `Low`/`High`/`Length`, value copy, array parameters and results; `A[I] += 1`.
- Fixed-width integers Int8, Int16, Int32, Byte/UInt8, UInt16, UInt32 are compiled with overflow and conversion range checks; a constant such as `B Byte := 200` or `B + 1` is read in the fixed-width type.
- `bitnot` is compiled.
- Module `State` variables (Integer, Natural, Bool, Float) are compiled; they are initialized in source order before `Main` runs.
- `case` and `unless` are compiled to native code (the selector is evaluated once).
- Precedence of `..` and `in` in CANON-20 (ADR-0008).
- Grouped declarations `A, B T := X`, with `X` evaluated once.
- Chained assignment `A := B := C := X` (ADR-0009).
- `for I in A..B step S` (ADR-0010).
- Ada/SPARK-style `case` with `|`, static ranges, and `otherwise` required unless coverage is proven (ADR-0011).
- Compound assignment `+=` `-=` `*=` `/=` `^=` (ADR-0012).
- Conditional expression `if C then A else B` (ADR-0013); only the chosen branch is evaluated.
- Digit separator `_` in numeric literals; hexadecimal as `$FF` or `0xFF`.
- A local variable that is never read is a compile error (OPEN-4).
- `Natural` is the non-negative subtype of `Integer` (0..Int64.Max, ADR-0014). As in Ada, storing an Integer into a Natural checks the range at run time with no conversion written (ADR-0015); a negative constant is a compile error.

### Changed
- The examples are in English (`bank-atm`, `contracts`, `file_io`, `method-reuse`, `pointers-navigator`, `pointers-tree` and the four `reuse-*` programs were in Portuguese), so every English speaker can read them; the code snippets of the language page (`docs/site/index.html`), the README and `Std.IOUtils` follow them. `bank-atm` now keeps its accounts in `inox-bank.txt` and `inox-bank-statement.txt`. The programs do the same as before; only names, messages and comments changed.
- Types are objects in the compiler (OpenSpec change `type-representation`, stage 1 of generics): `src/compiler/types/` holds one interned object per type (its kind, bits and range, fields, element, target), created by the analyzer and only read by the code generator, which maps each kind to the LLVM type it already offers (Bool `i1`, every integer `i64` with narrow storage in arrays, `float`/`double`, pointers, `[N x T]`, `%struct`). Codegen no longer re-reads written type text, re-parses signatures from tokens or infers types of its own. The compiler is a library (`inox-compiler`) with unit tests (`inox-compiler-tests`: types, LLVM layout, AST copies), and `ast/AstClone` copies statements with their type names replaced, as a generic instance will need. No program compiles differently: the IR, types, diagnostics and exit codes of all 633 programs are unchanged, except that struct types are now printed in declaration order (they followed the order of a hash table, which differs between Linux and Windows).
- Second syntax review (canon r3.76, change `syntax-review`): **no `Module` header** — a file is a module named after the file (`Use Calc.Core` loads `Calc.Core.inox` or `Calc/Core.inox`; the entry file may have any name), and a file that still starts with `Module Name` gets a message saying to remove the line; **`IIf(C, A, B)`** is the conditional expression, evaluating only the chosen branch, instead of `if C then A else B` (an `if` in an expression gets a message naming IIf); `leave` and `continue` are predefined names, as Break and Continue in Pascal; `Var` and `Module` are ordinary names (the `Var` block keeps its migration message); `pre`, `pos`, `old`, `invariant`, `variant` and `Override` are reserved. 42 reserved words, 10 predefined names.
- Fewer reserved words, 50 → 41 (canon r3.74, change `keyword-review`): the last arm of a `case` is `else` (`otherwise` is rejected with a message naming `else`); `True`, `False`, `Exit`, `bitand`, `bitor`, `bitxor` and `bitnot` are predefined names, unchanged in meaning, that can never be declared ("True is a predefined name of Inox and cannot be declared") but may name fields and methods; `Main` is an ordinary name. `{` and `}` are reserved for a future construct. `div` and `/` are unchanged.
- Module pairs (canon r3.64, OpenSpec change `module-pairs`): `Std.Files` now holds the File type and the basic operations (OpenRead, Create, OpenAppend, ReadLn, Eof, Write, WriteLn, Close); `Std.IOUtils` the conveniences (Exists, DeleteFile, RenameFile) and everything of Std.Files. Programs with `Use Std.IOUtils` are unchanged.
- `State` has no `:` (canon r3.62, OpenSpec change `state-without-colon`): `State`, its variables on the next lines, and `;`. `State :`, a State without its `;` and the old `Name : Type` form (also in `Const`) are rejected with a message showing the right form. `:` now appears only after a routine's name and signature.
- `Length(S)` of a String and `Ord(C)` of a Char are rejected (canon r3.62, change `char-not-ordinal`): `Length` takes an array or a slice, String lengths come with Std.StrUtils, and a Char is not an ordinal.
- The roadmap is renumbered for the version scheme (`docs/ROADMAP.md`, change `roadmap-renumber`).
- The canon becomes the constitution (canon r3.61, OpenSpec change `constitution`): `docs/INOX_CANONICAL.md` is retired; the language law lives, minimized and without duplicates or stale status, in `openspec/specs/constitution/` (`spec.md`, `engineering.md`, `revisions.md`), locked by `constitution.lock` and checked in CI by `tools/constitution_check.py`, which also verifies that every test a spec names exists. Status moves to `docs/STATUS.md` and `docs/ROADMAP.md`; the old change log is frozen in `docs/history/`. `inox --version` prints `(canon r3.61)`.
- Version scheme (canon r3.60): `MAJOR.MINOR.RELEASE.BUILD` plus the stage, today `0.2.0.<BUILD> pre-alpha`. The BUILD is the commit count of the compiled history, written at every build; `inox --version` prints e.g. `inox 0.2.0.206 pre-alpha (canon r3.60)`. CI clones the full history.
- Compiler sources (OpenSpec change `compiler-modularization`, step 4): `SemanticAnalyzer.cpp` (3,358 lines) is split into eight files by responsibility (declarations, built-ins, statements, constant evaluation, expressions, calls, types) and `SemanticSupport` for the shared helpers; types, diagnostics and IR are identical for every program.
- Compiler sources (OpenSpec change `compiler-modularization`, step 3): the exception ABI is a Strategy (`ItaniumExceptionAbi`, `MsvcExceptionAbi`) chosen once per module; the libinoxrt functions are one table (`RuntimeAbi`); the emitter tells the driver whether to link libinoxrt instead of the driver searching the IR text. The emitted IR is identical for every program, with both ABIs.
- Compiler sources (OpenSpec change `compiler-modularization`, step 2): `FunctionEmitter` gets its own header and nine source files by responsibility (control flow, exceptions, statements, I/O, String ownership, aggregates, arrays, expressions); `LlvmIrEmitter.cpp` keeps only the module emission (264 lines). The emitted IR is identical for every program.
- Compiler sources (OpenSpec change `compiler-modularization`, step 1): the support code of the LLVM emitter moves out of `LlvmIrEmitter.cpp` (5,154 → 3,704 lines) into `TypeLayout`, `AstQueries`, `LlvmText`, `Operators`, `MathBuiltins`, `ExceptionSupport` and `RuntimeHelpersIr`; the emitted IR is identical for every program. A stray `LlvmIrEmitter.cpp.diff` is deleted.
- Versioning (canon r3.58): Inox is `0.2.0-pre-alpha`; `inox --version` prints the version and the canon revision. The `v3.xx` numbers are canon revisions, written `r3.NN` from now on.

- The Windows test script feeds `.in` files to programs byte for byte and reads their output as UTF-8; `.gitattributes` keeps `.in` files unchanged by Git.
- A Type line `TName := Type` is an error: Inox has no type alias form (canon v3.54).
- Example files no longer carry the `llvm-` prefix (`examples/put-output-basic.inox`, ...).
- Windows (MSVC ABI): exceptions are lowered with LLVM funclets (`__CxxFrameHandler3`); every exception test passes natively on the CI runner (EH-v3.16a closed).
- `Var` blocks and scalars without an initializer are rejected (CANON-5).
- A bare `:` block inside a routine is rejected (CANON-4).
- `:=` is a statement, never an expression; named arguments only in struct construction (CANON-9).
- The `for` step form `(S)` is removed with a migration message.

### Fixed
- A String read from State, a `ref` parameter, a pointer path or a `with` binding could be freed by a routine called later in the same statement (`PutLn(Log = Mark)` with Mark assigning Log read freed memory); such a read is now held until the statement ends. Two empty literals in one line (`"" + ""`, `F("", "")`) lex as two Strings: the undocumented doubled-delimiter form is gone. `tools/string_leak_check.py` now instruments the generated code when clang has no ASan runtime of its own.
- `with` (canon r3.75, change `with-places`): a target other than a variable (`with Client.Comments`, `with A[I]`, a field of a `ref mut` parameter, an object through `Own` or `Link`, `Value(L)`) is lowered: evaluated once on entry, every `.Member` acting on its storage, and checked at each use through a pointer, so a `Free` inside the body stops the program. `with TClient` (a type) is rejected at the `with` line with a message that shows the named construction, instead of a truncated "unknown field" message at the first `.Member`.
- A String `Const` (`Const FileName := "data.txt"`) passed the analyzer and was not lowered; it is now a value like its literal.
- `Self` (without `mut`) could write its receiver, and the change reached the caller; a field of a value parameter could be assigned; `with` on a parameter could write it; a `Self mut` method could be called on a parameter or a literal; a `ref mut` argument could reach the receiver of the same call. All are rejected now (CANON-1, CANON-10, ADR-0016).
- A routine that takes arguments, called by its bare name (`Show` for `Show(N Integer)`), passed the analyzer and stopped in the backend; it is now "Show expects 1 argument, got 0". A function called as a statement is reported as a backend gap instead of a codegen error. Found by mutation fuzzing (seed 7).
- The release scripts copied a manual that no longer existed and did not ship `libinoxrt`, so packaging failed and packaged compilers could not build programs that use exceptions, Strings or Files; packages now hold the manual, the constitution and the runtime library beside the compiler.
- `=` and `#` on two Bool variables, `<` on Strings and `=`/`<` on structs passed the analyzer and then produced invalid IR. Bool and String comparisons now work; struct comparison is a compile error, as in Pascal (canon v3.56, v3.57).
- A function called with no arguments inside `try` (`N := Fail`) now reaches the handler; it was emitted with `call` instead of `invoke` and its exception aborted the program.

### Known limitations
- Not lowered yet: Float32 conversion.
- Vectors are not implemented; a Range over Char waits for Char values.
- String indexing (`S[I]`) and `GraphemeLength` are reserved; collation, normalization, Split/Join and conversions between numbers and text come later; slices of String arrays are not supported yet.
- Generic types other than `Slice<T>` (`Vector<T>`, `Set<T>`) are not parsed yet.
